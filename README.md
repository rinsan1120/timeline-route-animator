# Journey Map Studio

Journey Map Studioは、Googleマップのタイムラインから移動実績を読み込む「移動実績参照モード」、地図上で旅程を作る「計画モード」、地図画像を制作する「スポット画像モード」を備えたWebアプリです。移動実績では開始日・終了日と時間帯を選んでルートを編集できます。動画のプレビュー・FHD MP4出力や地図のPNG出力に対応し、元のタイムラインJSONは端末外へ送信しません。

計画・スポット画像モードでは施設名・地名・カテゴリ・ブランドをOpenPOI APIで全国検索でき、「緯度, 経度」の直接入力も使えます。3文字以上の入力補完は300ms待って最大5件、「検索」ボタン／IME変換中でないEnterによる本検索は1〜2文字でも最大15件取得し、有効な結果をすべて表示します。多い場合は一覧部分だけを縦スクロールできます。施設の選択は紫の参考位置を表示し、地域の選択は範囲へ移動します。地点は自動追加されません。紫の照準は一時表示のみで、Undo／Redo・保存JSON・プレビュー・MP4・PNGには含まれません。「消す」またはモード終了で破棄されます。検索結果には誤データが含まれる可能性があるため、地図で確認してから手動で地点を追加してください。

## 主な機能

- Timeline JSONをWeb Worker内で解析（日付index、`timelinePath`、`rawSignals.position`）
- `activity.topCandidate.type`に依存しないルート抽出
- 開始日・終了日とFrom / Toによる複数日にまたがる範囲抽出、および読み込み後のDAY別表示・出力
- MapLibre GL JS + 国土地理院のベクトルタイルを基本とした地図表示（陸地補完・地形表示の現行設定を使用）
- ルートポイントの追加、連続追加、ドラッグ移動、削除
- Undo / Redo / 初期状態への復元（PCではCmd/Ctrl+Z、Cmd/Ctrl+Shift+Zにも対応）
- rawSignalsの参考表示と精度別の色分け
- 累積距離に基づく一定速度アニメーション
- バルーン表示時の共通停止時間を0.5秒刻み（0〜30秒、初期0秒）で設定
- 通常編集画面のルートをDAYごとの固定色で表示
- 全ルート表示 / 通過済みルート表示
- 設定項目や計画モードの編集ツールにある「?」から簡単な説明を表示
- WebCodecs + Mediabunnyによる1920×1080・30fps・H.264 MP4生成
- 計画モードのルート・地点バルーン・DAY情報を専用JSONへ保存し、後から編集を再開
- 移動実績参照モードでも編集途中の状態を作業JSONへ保存し、元のJSONファイルなしで後日再開

元のGoogleマップからエクスポートしたJSONファイルはアップロード、外部API送信、localStorage保存を一切行いません。地図の表示には国土地理院の地理院地図Vectorを中心とする地図データ・関連リソースへのネットワーク接続が必要です。地図の出典表記は現在の地図ソース設定に従います。

OpenPOI場所検索を使用した場合だけ、入力した検索語をOpenPOI APIへ送ります。Timelineの内容・座標、計画ルート・スポットの座標、現在地、地図中心・表示範囲（bbox）、center・radiusはOpenPOIへ送りません。緯度経度の直接入力は端末内で処理し、OpenPOIへ送信しません。検索語・候補・結果・参考位置は永続保存せず、計画／作業JSONにも含めません。検索データ：[OpenPOI API](https://openpoiapi.com/attribution.html)。

## 対応ブラウザ

- Android版Google Chrome最新版（最優先）
- Windows / macOS版Google Chrome最新版
- iPhone Safari／iOS Chrome、Samsung Internet、macOS Safari、Windows Edge等も画面設計上の考慮対象です。ただし、各ブラウザ・端末での実機動作やMP4生成対応を保証するものではありません。

MP4生成にはWebCodecsのH.264エンコーダーが必要です。非対応環境では日本語のエラーを表示します。端末性能や空きメモリによってはFHD生成に時間がかかります。

## セットアップ

Node.js 20以降を用意してください。

```bash
npm install
npm run dev
```

表示されたローカルURLをChromeで開きます。

## テストとビルド

```bash
npm run test
npm run build
```

`sample-data/`に実Timeline JSONがある場合、テストはそのファイルも自動で解析します。位置や時刻はテスト出力へ表示しません。`sample-data/`、`*.private.json`、Timelineの標準ファイル名は`.gitignore`で除外されています。

## 操作方法

スマホ（幅760px以下）では、設定パネルが地図の下部に重なります。初期状態は閉じており、上部ハンドルのタップで開閉、上スワイプで「閉じる→半開き→全開」、下スワイプで逆順に切り替えます。マウスでのドラッグや、ハンドルにフォーカスして上下矢印キーでも操作できます。開いた状態のStep 01／02／03は既存の設定欄への移動ボタンです。設定欄の中は独立して縦スクロールします。地図を広く操作するときはパネルを閉じてください。開閉状態はJSONやUndo／Redoには含まれません。

1. 「移動実績参照モード」で、GoogleマップからエクスポートしたJSONファイルを選びます。
2. 開始日・終了日とFrom / Toを指定して「この範囲を読み込む」を押します。読み込み後は「表示・出力する日程」で全日程または特定DAYを選択できます。
3. 「編集」に切り替えます。ポイントをタップして選び、大きなオレンジのハンドルをドラッグして移動します。
4. 「連続追加」を選ぶと、地図をタップするたびに最も近いルート区間へ手動点を挿入します。道路スナップや自動補完は行いません。
5. 必要に応じて「測位データを表示」を有効にし、参考点をタップして測位方法や測位精度を確認します。測位データはルートへ自動追加されません。
6. Step 03でバルーン表示時の共通停止時間、動画時間とカメラを設定し、必要に応じて「映像で確認」してから「MP4を生成」を押します。
7. 完了後、「MP4を保存」から`route-YYYY-MM-DD.mp4`を保存します。

地点ラベルがある地点では、バルーン表示時に共通秒数だけ停止します。地点マーカーがDAYの場合はDAY 2以降の開始地点でも停止し、両条件が同じ地点に重なっても1回だけです。DAY 1表示だけでは停止せず、先頭地点にラベルがある場合は停止します。アニメ範囲外は対象外、0秒なら停止なしです。開始前の時間と到着後の停止はそれぞれ0〜30秒・0.5秒刻みで設定でき、初期値は各3秒です。開始時ズームがONなら開始前の時間をズームに使い、OFFなら開始地点で静止します。出力時間は開始前＋移動時間＋地点停止合計＋到着後で、プレビューも同じ時間です。これらの動画時間設定は作業JSON・計画JSONへ保存します。旧JSONのポイント別pauseSecondsは受理・保持しますが、再生には使用しません。

通常編集画面ではDAYごとにルートを固定色で表示し、DAYマーカーの外枠・コネクタ・アンカーも同じ色にします。色は10色のパレットを循環し、DAY11はDAY1と同じ色へ戻ります。動画ではStep 03の「DAYごとにルートを色分け」でプレビュー・MP4の色分けを切り替えられ、ONの場合はDAYマーカーのアクセントと走行距離HUDの各DAY行にもルートと同じ色を表示します。

### 動画プレビューの画角

「映像」画面で停止し、映っている地点バルーンをクリック／タップすると選択枠が付きます。そのままドラッグして位置を調整できます。再生中に編集対象（地点バルーン・DAY・START／GOAL・距離HUD）をタップすると停止して対象を選択します。再生中の空白タップでは停止せず、選択状態を維持します。停止中の空白タップは選択を解除します。画面上で約6px未満の移動は選択だけで、移動確定はUndo履歴1件です。「元に戻す／やり直す」は地図と同じ履歴を使います。バルーンにフォーカスして矢印キーで動画座標5px、Shift併用で20pxずつ微調整できます。ドラッグ中に画面を離れる・操作がキャンセルされる場合は確定せず元へ戻ります。

地点詳細の「映像で確認」は、対象バルーンが動画で初めて表示されるフレームへ移動し、対象の選択まで行います。アニメ範囲外や動画内に映らない地点には案内を表示し、カメラを勝手に動かして表示させません。停止中の映像の空白をタップすると、バルーン・DAY・START／GOAL・距離HUDの選択枠を消して完成映像だけを確認できます。ガイドはMP4・JSON・鮮度判定に含みません。ドラッグ中は再生・シーク・MP4生成／保存を開始できません。

バルーン位置は従来と同じ0〜1のframePositionで作業JSON・計画JSONへ保存し、再生成したMP4へ反映します。左右・上24px、出典用の下70pxを確保し、サイズ変更時も全体を有効領域へ収めます。接続線は同じフレームの地点へつながります。Step 02の旧配置専用ボタンと構図確認セレクターは映像編集へ集約しました。通常の地図編集と旧JSONの配置補完、スポット画像の配置方法は維持しています。

「映像」画面は全体表示・追従表示とも1920×1080のMP4と共通のCanvas描画を16:9で縮小表示します。バルーンのヒット領域も共通のCanvas寸法から配置し、表示倍率に合わせて保存位置を変更することはありません。映像の再生・シークで編集地図のカメラは変更しません。

移動実績参照モード／計画モードで「ルート追従」を選ぶと「追従視点」を切り替えられます。初期値の「真上」は従来どおり北を上にした傾き0°の表示です。「斜め」は45°傾け、開始地点→ルート距離50%の中間地点、中間地点→終了地点の2方向を使用します。中間地点に到達してから移動時間で2秒（残り移動時間が短ければその時間内）かけ、最短方向へ滑らかに旋回します。バルーン停止・DAY切替・カメラパン中は旋回も止まります。アニメ範囲を指定した場合はその範囲内で計算し、細かなGPSの蛇行を追って向きを変えません。

斜め視点でも従来のカメラ中心・Zoom・パン計画を使用し、映像画面とMP4で同じ方位・傾きを適用します。開始時ズーム中も最初から斜めの視点を維持します。編集地図のカメラはそのまま保持します。視点設定は作業／計画JSONへ保存します。動画設定はUndo/Redoの対象外です。スポット画像モードには追加していません。

### 計画モードの概算距離

計画モードの「編集」ツールバーには「選択」「連続追加」「途中追加」「範囲削除」があります。「連続追加」は末尾へ追加し、「途中追加」はクリック位置に最も近い同一DAY内の区間へ挿入します。クリックした緯度経度はそのまま使い、道路やルート線へ吸着させません。途中追加は2点以上で利用でき、追加後も継続できます。DAY境界をまたぐ区間は候補に含めず、候補がなければエラーを表示します。追加した点はUndo／Redo・計画JSON保存の対象になります。

Step 02「ルートを整える」にDAY別の概算距離と合計を表示します。登録ポイント間の地表上の直線距離を合計し、DAY境界をまたぐ区間は除外します。道路に沿った走行距離ではありません。ポイント編集・Undo / Redo・DAY設定変更・作業再開に合わせて更新され、見出しにも同じ合計を表示します。

### 移動実績参照モード／計画モード共通の概算距離HUD

DAYマーカーの動画用寸法は1920×1080基準（最小幅230px、DAY文字24px等）で固定し、生成端末やブラウザviewportに依存しません。動画プレビューは同じ論理レイアウト全体を動画フレームの倍率で縮小します。通常編集画面では操作しやすい従来のCSS寸法を維持します。画面幅760px以下では、DAYマーカー選択時の編集欄に「DAY編集表示サイズ」を表示し、75〜175%（25%刻み、初期100%）で調整できます。動画プレビュー・MP4・保存済み配置には影響せず、計画JSONにも保存しません。日付・補足の有無や文字幅を反映し、保存済みの配置offsetの意味は変更しません。

Step 03「動画を確認・出力する」の「走行距離表示」をONにすると、移動実績参照モード／計画モードともに地図とMP4（overview／follow）にDAY別・TOTALの概算距離HUDを表示します（初期OFF）。編集画面ではルート全体の最終距離、プレビューと動画では現在地点までの距離をkm小数1桁で表示します。アニメ範囲の途中開始では、それ以前の走行距離も含みます。DAY間の接続区間やカメラ移動だけの間は加算しません。

両モードともポイント間距離を積算した概算値です。GPSの記録飛びや道路形状との差によって実走行距離とは異なる場合があります。移動実績のDAY番号は欠測日があっても再採番せず、既存の番号とDAY色を維持します。

サイズは50〜200%で調整でき、地図上のHUDをドラッグすると1920×1080の動画フレーム内で位置を変更できます。「位置をリセット」で左上へ戻せます。DAY数などによりパネルが動画より大きくなる場合は、全体が収まる倍率まで縮小します。プレビュー・動画生成中は配置変更できません。HUDの表示・位置・サイズは作業JSON・計画JSONへ保存します。動画設定のない旧JSONや新しい作品ではOFF／100%／初期位置へ戻ります。

### 移動実績参照モードの表示・出力日程

Step 01の開始日・終了日の下にある「表示・出力する日程」で、全日程または読み込み済みの特定DAYを選べます。選択DAYだけを地図・プレビュー・MP4・距離HUD・停止時間計算に使用し、元のDAY番号を維持します。手動追加点もDAY境界内に含めます。DAY内で編集しても非表示の日程は削除しません。

DAYを切り替えるとポイント選択・アニメ範囲・プレビューを解除します。新規読込・範囲再抽出では「全日程」に戻ります。作業JSONには常に全行程の編集済みポイントとDAY選択状態を保存します。作業再開時は保存した日程を選び、設定がない旧JSONや該当日程がない場合は「全日程」に戻ります。計画モードにはこの選択を追加していません。

### 地図と映像の作業画面

移動実績参照・計画モードで動画対象ルートが2地点以上になると、表示領域の上部に「地図／映像」が現れます。「地図」はルートと地点を編集する画面、「映像」は完成映像の構図を確認する画面です。切替はスマホの設定シートを閉じたまま操作できます。地図は切替時も保持され、戻ると編集状態と構図を引き継ぎます。

Step 03の「映像で確認」からも映像画面を開けます。「再生／一時停止」、1フレーム単位のシークバー、前後のイベント・イベント一覧から位置を移動できます。STARTは移動開始、DAYとバルーンは動画で初めて表示される位置、GOALは到着位置です。DAYはDAYマーカー有効時のみ表示し、動画内に表示されないバルーンは理由付きのジャンプ不可項目になります。同じフレームの印はまとめ、一覧では個別に選べます。

1920×1080の完成フレームを16:9で縮小表示します。時刻欄は表示中の映像、シークバーは要求した位置を示し、シーク準備中は直前の完成映像を保ちます。端末性能によって中間フレームを省略します。一時停止・地図への切替・タブ非表示では最後の表示位置で停止し、映像へ戻ると同じ位置を復元します。最終フレームでは自動停止し、再生を押すと先頭から再開します。準備失敗時は「再試行」を押してください。

映像を見ながら既存の設定欄を操作すると自動停止し、新しい設定を反映します。カメラ・サイズ・HUD等は原則同じフレーム、時間軸が変わる変更は選択イベント（未選択なら表示中の経過秒数）を保ちます。イベントが消えたり表示不可になった場合は選択を解除して経過秒数を使い、動画が短くなれば終端に収めます。手動シークや通常再生ではイベント基準を解除します。設定反映中は更新表示を出し、自動再生は再開しません。地図での編集も映像へ戻ると反映され、地図の構図・編集履歴、スマホ設定シートの開閉状態は維持します。

映像確認は必須ではなく、地図からそのまま「MP4を生成」できます。MP4生成前に映像確認用の地図を解放し、生成中は直前に表示できた映像を静止させて進捗を重ねます。完了・キャンセル後は元の位置へ停止状態で戻ります。作業画面の選択・再生位置・再生状態はJSONへ保存せず、新しい作品は地図画面から始まります。スマホでも再生・シーク・イベント操作は設定シートの外にあり、一覧は通常閉じています。長い選択イベント名は省略しますが、一覧では全文を確認できます。狭い表示領域では操作を折り返し、収まらない操作欄は縦スクロールできます。設定シートを閉じると映像と主要操作を広く使えます。画面回転でも再生位置・選択・確定したバルーン位置は維持します。

MP4生成後にルート・バルーン・動画設定など出力内容を変更すると、Step 03に「再生成が必要」と表示し、「MP4を保存」を無効にします。「MP4を再生成」で更新してください。Undoや設定の戻しで生成時と一致すると、保持しているMP4を再び保存できます。再生・シーク・地点選択・画面切替・編集地図のパン／Zoomでは古くなりません。再生成の失敗・キャンセルでも以前の正常なMP4は保持しますが、別作品の開始／読込では破棄します。MP4と鮮度情報は作業JSON・計画JSONには保存しません。

### 移動実績参照モードの作業保存・再開

Step 01の「作業を保存」で、現在の編集済みポイントを`route-work.json`を初期候補名として端末へ保存します。「作業を再開」でこのファイルを選ぶと、元のGoogleマップからエクスポートしたJSONファイルなしで編集を続けられます。再編集・再保存も繰り返せます。上部の「移動実績参照モード」でも作業JSONを自動判別して同じ状態を復元します。元データは従来どおりWorkerで解析し、種別判定では先頭4KBだけを確認します。計画JSONは計画モードの「作業を再開」で読み込みます。

保存対象はポイントID・順序・座標・由来・日時・旧停止時間（互換用）・地点バルーンの文言と配置、開始日／終了日とFrom／To、DAY補足と配置、START／GOAL配置、文字サイズとバルーンの最小幅・適用対象、アニメ範囲、表示・出力する日程、動画設定（時間・カメラ・Zoom・開始時ズーム・マーカー・DAY色分け・実績時計・距離HUD）です。DAY境界と番号は保存したポイントの日時と開始日から従来どおり生成します。削除したポイントは復活しません。

元のGoogleマップからエクスポートしたJSONファイル、測位データ、Undo／Redo履歴、選択・再生・生成中の一時状態、スマホDAY編集表示倍率は保存しません。動画設定のない旧JSONは既定値で再開し、保存済みの配置・アニメ範囲は維持します。旧バルーンサイズ倍率は100%へ正規化し、最小幅設定のない旧JSONは280px・DAY／通常バルーンとも適用OFFで読み込みます。再開したポイントが新しい「初期状態」になり、測位データは空・非表示になります。再開後は日付・時間を表示しますが、元データがないため期間の再抽出は無効です。作業JSONは端末内だけで処理し、元JSONは変更しません。

### 計画モードの作業保存・再開

「計画モード」の「旅のルートを準備する」内で、1点以上あるときに「作業を保存」を押すと、`route-plan.json`を初期候補名として端末へ保存します。「作業を再開」からこのファイルを選ぶと、現在のルートを保存状態へ置き換え、ポイントID・地点バルーンの文言と配置・DAY区切り・DAY補足と配置に加え、文字サイズとバルーンの最小幅・適用対象・アニメ範囲・START／GOAL配置・動画設定を復元します。

Undo / Redo履歴は含みません。追加設定のない旧計画JSONも読み込め、保存されていない動画設定・サイズ・範囲・START／GOAL配置は既定値へ戻します。再開した状態が新しい初期状態になります。ヘッダーの「移動実績参照モード」は元のGoogleマップからエクスポートしたJSONファイルと作業JSONに対応します。計画JSONはサーバーへ送信されませんが、位置情報を含むため取扱いに注意してください。

### JSON・MP4の保存先と名前

対応ブラウザでは「作業を保存」「MP4を保存」を押すたびに保存ダイアログを開き、名前・保存先・既存ファイルへの上書きを選択できます。作業JSONは再開時のファイル名、保存後は選んだファイル名を次回の候補にします。ファイルハンドルは保持せず、自動上書きは行いません。キャンセル時は保存もダウンロードも行いません。非対応ブラウザでは従来のダウンロード方式を使用します。MP4の保存ダイアログは生成完了時ではなく「MP4を保存」を押したときだけ開きます。

## GitHub Pagesへ公開

`vite.config.ts`のbaseはProject Pagesの公開パス`/timeline-route-animator/`に設定されています。

1. GitHubリポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** に設定します。
2. `main`へpushすると、`.github/workflows/deploy.yml`がテストとビルドを実行し、生成された`dist/`だけをPagesへ公開します。
3. Actionsの「Deploy to GitHub Pages」が完了してから公開URLを開きます。リポジトリ直下を直接Pagesへ公開すると、未ビルドの`/src/main.tsx`が参照されてアプリは起動しません。

実Timeline JSONや`sample-data/`はpushしないでください。

## 実装上の制約

- ルート本体には`semanticSegments[].timelinePath`だけを使用します。
- `rawSignals.position`は人間が補正するときの参考表示専用です。
- activity type、Routing API、道路スナップ、AI推定、自動GPS補完は使用しません。
- 動画生成は専用MapLibre mapと共通のCanvasフレーム描画を使用します。全体表示でカメラが固定される区間では背景をキャプチャして再利用し、ルート追従・開始時ズーム等のカメラが変化する区間では必要に応じて地図を準備・描画します。
- 地図タイルの読み込み失敗や欠落に対しては、現在のGSI地図用の補完・エラー処理を使用します。動作や動画出力が常に成功するとの保証はしません。
- 地図の共通styleは`src/map/gsiStyle.ts`、データソース・出典・配色やZoom等の構成は`src/map/gsiVectorConfig.ts`ほかGSI関連設定に定義されています。主要ベクトルタイルは`https://cyberjapandata.gsi.go.jp/xyz/experimental_bvmap/{z}/{x}/{y}.pbf`で提供され、補助的な地形・陸地データ等を組み合わせます。従来の`src/map/osmStyle.ts`とOSM標準ラスタータイルの説明は現行実装には該当しません。
- 数十MBのJSONでもUIを長時間止めないよう、ファイルの読み取り・`JSON.parse`・index作成・範囲抽出はWorkerで行います。ただし標準の`JSON.parse`自体は全体を一度メモリへ展開します。
- 現行実装には複数日にまたがる範囲指定、DAY別の表示・出力、ルート追従カメラ、斜め視点、開始時ズームがあります。古いV1の機能制約を現在の仕様として扱わないでください。4K・60fps等への対応は実装コードと承認済み仕様を確認して判断します。
